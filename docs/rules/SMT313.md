# SMT313 definition-order

Definitions can follow the configured order without violating modeled execution dependencies.

- **Category:** structure
- **Activation:** policy — A package contract enables ordering.
- **Severity when active:** error

## Why

Public interfaces should be easy to find. A stable topological order prioritizes configured categories while preserving category order, definition-time reads, rebinding and execution barriers. Function bodies are deferred; decorators, defaults, assignments and eager annotations are not. Future imports and declared Python 3.14+ targets defer annotations. Overload/property families remain atomic. Unknown execution is pinned.

## Bad

```python
def _load():
    return 1

def get():
    return _load()
```

## Good

```python
def get():
    return _load()

def _load():
    return 1
```

## How to fix

Review the expected order and execution barriers. Explicit check --fix can apply bounded moves where the package permits safe-only fixes. Imports, unknown execution and a misplaced main guard require manual review. Names and visibility are never rewritten by ordering.
