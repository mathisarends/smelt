# SMT108 package-import-fanout

One caller imports many implementation modules of the same package.

- **Category:** dependencies
- **Default severity:** hint

## Why

Repeated imports of neighboring implementation modules can indicate a missing package API. This is an opt-in design hint, not proof of poor architecture. Count distinct target modules per source file and contracted package, not statements, symbols, or imports across the whole repository.

## Bad

```python
# caller.py
from app.users.application.get_user import GetUser
from app.users.application.update_user import UpdateUser
from app.users.application.delete_user import DeleteUser
```

## Good

```python
# caller.py, after deliberate facade exports are defined
from app.users.application import DeleteUser, GetUser, UpdateUser
```

## How to fix

Consider exporting the caller's supported API from the package facade. Check dependency direction and cycles before changing exports. If these independent dependencies are intentional, retain them or adjust the advisory threshold. Declare public: ['.'] to enforce facade-only imports.
