# SMT425 test-only-checks-possibly-empty-data

Every recognized outcome can disappear or pass trivially on empty input.

- **Category:** tests
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** warning

## Why

Assertions confined to a result-dependent loop never execute if the result is empty. A positive all(...) assertion also accepts an empty collection. This opt-in review aid reports tests whose entire recognized evidence has one of these shapes. Literal nonempty iteration without filters, explicit empty-result comparisons and tests with an additional independent outcome check are retained. It does not prove collection cardinality, reachability or test effectiveness, and can flag intentional universal properties over empty collections.

## Bad

```python
def test_codegen():
    for name, content in generate().items():
        assert committed[name] == content
```

## Good

```python
def test_codegen():
    assert generate() == independently_loaded_committed_files()
```

## How to fix

Compare the complete result with an independent expectation, or check expected presence/cardinality before universal checks. Keep intentional empty-result cases explicit; do not add cosmetic assertions.

## Config

- `rules`
- `tests.assertion_helpers`
- `tests.quality_exclude`
