# SMT347 anonymous-tuple-type

A fixed-length tuple type leaves its fields unnamed.

- **Category:** structure
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** hint

## Why

dict[UUID, tuple[UUID, UUID, BrowserConnection]] does not say which UUID is which; readers decode entry[0] and entry[1] from call sites, and swapping them still type-checks. This opt-in review reports fixed-length tuple types in annotations and type aliases with three or more elements, or with an element type that repeats. Variadic tuple[X, ...], empty tuples, two different element types, quoted annotations, dunder/@override/@overload signatures (dictated elsewhere) and tests are not reported.

## Bad

```python
class Connections:
    def __init__(self) -> None:
        self._by_tab: dict[UUID, tuple[UUID, UUID, Connection]] = {}
```

## Good

```python
class Route(NamedTuple):
    user_id: UUID
    run_id: UUID
    connection: Connection

class Connections:
    def __init__(self) -> None:
        self._by_tab: dict[UUID, Route] = {}
```

## How to fix

Introduce a NamedTuple (keeps unpacking and indexing) or a frozen dataclass that names each field, and use it in place of the tuple. Keep a tuple whose shape an external API dictates with a reasoned suppression. No automatic rewrite is performed. Enable rules: {anonymous-tuple-type: hint}, or select SMT347.
