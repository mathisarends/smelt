# SMT103 third-party-denied

A layer imports a third-party package its `third_party` policy does not allow.

- **Category:** dependencies
- **Activation:** policy — A layer's third_party policy restricts dependencies.
- **Severity when active:** error

## Why

Inner layers should not know about frameworks, drivers or SDKs. Keeping them out makes the core portable and cheap to test. With architecture.imports.transitive, the importing layer's policy also applies to packages reached through project modules, such as domain -> shared.utils -> sqlalchemy. A shortest chain includes each import's source line. External packages are leaves: their own source is not scanned. Standard-library imports remain allowed.

## Bad

```python
# voice/domain/session.py
from sqlalchemy.orm import Mapped
```

## Good

```python
# voice/domain/session.py
from dataclasses import dataclass
```

## How to fix

Move the code that needs the package into a layer that allows it and expose it through a port, or extend the layer's `third_party` policy.

## Config

- `architecture.layers.<layer>.third_party.default`
- `architecture.layers.<layer>.third_party.allow`
- `architecture.layers.<layer>.third_party.deny`
- `architecture.imports.transitive`
- `architecture.imports.type_checking`
