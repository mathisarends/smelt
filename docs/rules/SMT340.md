# SMT340 await-in-call-argument

An awaited result is passed directly as a call argument.

- **Category:** structure
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** hint

## Why

Naming an awaited result before passing it on separates the suspension point from the construction or call that consumes it, and gives the value a name in tracebacks and debuggers. This opt-in review reports an await expression that is a direct positional or keyword argument of a call in production code, including nested forms such as await f(await g()). Plain awaits, return await, assignments, awaits nested inside containers or other expressions and calls without await, such as asyncio.gather(f(), g()), are not reported. Awaits in comprehensions, lambdas, conditional expressions, boolean operators and while conditions are skipped because extracting them would change when or how often they run. Tests are not checked. Extracting an argument evaluates it before the arguments to its left; review order-sensitive calls.

## Bad

```python
async def read(browser: Browser) -> ClipboardResult:
    return ClipboardResult(text=await browser.clipboard.read())
```

## Good

```python
async def read(browser: Browser) -> ClipboardResult:
    text = await browser.clipboard.read()
    return ClipboardResult(text=text)
```

## How to fix

Assign the awaited result to a local variable in the statement before the call and pass that variable. For a keyword argument the keyword is suggested as the variable name. No automatic rewrite is performed. Enable rules: {await-in-call-argument: hint}, or select SMT340. Package overrides and reasoned inline suppressions are supported.
