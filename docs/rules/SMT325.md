# SMT325 missing-module-docstring

A module lacks the non-empty docstring required by its package convention.

- **Category:** structure
- **Activation:** policy — A package contract requires module docstrings.
- **Severity when active:** error

## Why

A consistent module introduction helps readers understand each file's responsibility. With module_docstrings: require, every analyzed production module in the package needs a non-empty initial docstring, including empty files, __init__.py and __main__.py. Comments, later strings, bytes, f-strings and class/function docstrings do not satisfy the policy. Blank docstrings are reported too. Choose forbid for the opposite convention (SMT309); allow explicitly exempts a nested package. Omitted policy adds no requirement. Only analyzed source files are checked; separately discovered tests and excluded files are unaffected.

## Bad

```python
VALUE = 1
```

## Good

```python
"""Constants for the calculation service."""
VALUE = 1
```

## How to fix

Add a useful module docstring before imports and other statements. Mark an intentional file exception with # smelt: ignore-file[SMT325] -- reason. No documentation is generated automatically.

## Config

- `structure.contracts`

Explain it in the terminal with `smelt explain SMT325`.
