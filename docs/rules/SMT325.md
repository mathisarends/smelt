# SMT325 package-only-dunder-all

An ordinary module declares __all__ outside a package initializer.

- **Category:** structure
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** error

## Why

This opt-in convention puts deliberate export lists in __init__.py so a package has one visible public facade. It reports module-scope __all__ bindings, including guarded, annotated, augmented and imported bindings. Function/class-local names and test files are outside scope. Package initializers may declare __all__; SMT313 independently checks definition order. This is an API convention, not a claim that Python forbids ordinary module exports.

## Bad

```python

# app/events.py
def open_events(): ...
__all__ = ["open_events"]
```

## Good

```python

# app/events.py
def open_events(): ...

# app/__init__.py
from .events import open_events
__all__ = ["open_events"]
```

## How to fix

Review the package API and move the deliberate export list to __init__.py, preserving intended re-exports and checking cycles. Removing __all__ can change star imports and the visibility evidence used by other rules. No list is moved or removed automatically. Enable rules: {package-only-dunder-all: error}; closest package overrides can retain compatibility modules.
