# SMT429 test-only-public-function

A public module function is accessed from tests but has no observed production use outside its own module.

- **Category:** tests
- **Activation:** policy — tests.review_test_only_public_functions is enabled.
- **Severity when active:** warning

## Why

Leaving an internal helper public just so tests can call it enlarges the apparent API and couples tests to implementation details. This opt-in review identifies undecorated top-level sync/async functions without a leading underscore, referenced by analyzed tests and not imported or accessed by another analyzed production module. Uses inside the defining module do not justify public visibility. Aliased/relative imports and analyzed re-exports are resolved; production imports, star imports and escaped module values conservatively preserve the API. Explicit __all__ exports, dynamic export declarations, decorated functions, rebound names, methods and nested functions are excluded. Test-quality exclusions apply to test evidence. External consumers, packaging entry points and arbitrary dynamic access are not fully known; a finding is a review candidate, not proof that a function can be made private safely.

## Bad

```python
__all__ = ['drag']
async def drag_gesture(tab): ...
async def drag(tab):
    await drag_gesture(tab)
# tests/test_mouse.py
from app.mouse import drag_gesture
```

## Good

```python
__all__ = ['drag']
async def _drag_gesture(tab): ...
async def drag(tab):
    await _drag_gesture(tab)
# tests/test_mouse.py
from app.mouse import drag
```

## How to fix

If this is an internal helper, add a leading underscore and update internal references. Prefer testing the public behavior that calls it. If direct helper tests are deliberate, keep a reasoned private-access exception; if it is a supported external API, declare it in __all__ or document a reasoned suppression. Review callers before renaming.

## Config

- `tests.review_test_only_public_functions`
- `tests.quality_exclude`
