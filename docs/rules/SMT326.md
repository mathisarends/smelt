# SMT326 no-base-class-suffix

A class definition ends in the Base suffix forbidden by the selected convention.

- **Category:** structure
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** error

## Why

MessageBase and _MessageBase describe an inheritance role instead of the abstraction's responsibility. This opt-in naming convention checks production class definitions, including private, nested and local classes. Imported names, aliases, base-class expressions and test files are not renamed or rejected. It complements SMT323 without changing that rule's prefix contract. A bare Base belongs to SMT323; Database, Base64 and responsibility-based class names remain valid.

## Bad

```python
class _MessageBase:
    ...

class AssistantMessage(_MessageBase):
    ...
```

## Good

```python
class Message:
    ...

class AssistantMessage(Message):
    ...
```

## How to fix

Name the class after its responsibility or contract and update references and deliberate exports. Keep intentional inheritance. Enable rules: {no-base-class-suffix: error}; package overrides or a reasoned suppression can preserve a published name. No automatic rename is performed.

## Config

- `rules`
- `structure.contracts`

Explain it in the terminal with `smelt explain SMT326`.
