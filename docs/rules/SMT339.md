# SMT339 private-symbol-import

Production code imports or reads another project module's private symbol.

- **Category:** structure
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** warning

## Why

A leading underscore marks a symbol as private to its module, including when callers are sibling modules in the same package. This opt-in review checks relative and absolute from-imports and module-qualified reads through lexical import aliases. Only symbols statically resolved to definitions in analyzed production modules are included. Third-party and unknown names, private module names, dunders, instance/class members, reflection and same-module access are excluded. Public aliases remain public. A package initializer may re-export its own submodule's private symbol under a public alias. Tests remain covered by SMT420. TYPE_CHECKING follows architecture.imports.type_checking. Rebound, shadowed or wildcard import bindings are conservatively skipped for qualified reads; dynamic assignments and arbitrary alias propagation are not inferred. No analyzed code is executed.

## Bad

```python
# app/client.py
from .service import _normalize

```

## Good

```python
# app/client.py
from .service import normalize

```

## How to fix

Give a shared helper a module-public name, keeping it out of __all__ and the package facade when it is internal to the package, or move it into the module that uses it. Review callers before renaming; no automatic rewrite is performed. Enable rules: {private-symbol-import: warning}, raise its severity to error, or select SMT339. Keep intentional access with a reasoned SMT339 suppression on the imported name or read.
