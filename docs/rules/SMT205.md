# SMT205 container-usage

A DI container resolves a dependency outside the composition root.

- **Category:** code
- **Default severity:** error

## Why

Pulling dependencies out of a container (service locator) hides them from signatures, so neither readers nor tests can see what a class needs.

## Bad

```python
def start(container: Container) -> None:
    sessions = container.get(VoiceSessionRepository)
```

## Good

```python
def start(sessions: VoiceSessionRepository) -> None: ...
```

## How to fix

Take the dependency as a parameter and resolve it in the composition root.

## Config

- `architecture.composition_root`
- `architecture.di_frameworks`

Explain it in the terminal with `smelt explain SMT205`.
