# SMT423 excessive-test-patches

A collected test exceeds its configured number of recognized patch calls.

- **Category:** tests
- **Default severity:** error

## Why

Many replacements can indicate a test coupled to construction and internal calls. Count patch operations in decorators and the test body once per syntactic call, including patch.object. Nested helper bodies, fixtures and transitive calls are not attributed to callers. The limit is a configurable convention, not a proof that a test is bad.

## Bad

```python
def test_run(mocker):
    mocker.patch("app.one")
    mocker.patch("app.two")
```

## Good

```python
def test_run():
    result = run(InMemoryRepository())
    assert result.status == 'active'
```

## How to fix

Reduce the scenario's dependencies or inject a fake. Keep a justified integration scenario with a reasoned exception rather than hiding patches inside helpers.

## Config

- `tests.max_patches_per_test`
- `tests.quality_exclude`

Explain it in the terminal with `smelt explain SMT423`.
