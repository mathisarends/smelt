# SMT109 facade-export-gap

A public implementation name has many outside importers but no package export.

- **Category:** dependencies
- **Activation:** policy — A package contract sets export_at.
- **Severity when active:** hint

## Why

A contract's export_at threshold counts distinct analyzed modules outside the defining package, aggregating aliases and static re-export chains. One advisory finding per symbol and facade is anchored at the definition. Tests count only with count_tests: true; TYPE_CHECKING-only imports never count. Private names, module imports, namespace packages, uncertain bindings and recognized dynamic facade exports are skipped. Existing package exports and explicit __all__ re-exports in other modules are context, not coverage for this facade. Frequency suggests an API review, not a requirement to expand the public API. Counts cover analyzed code only. Optional structure.canonical_exports maps a qualified definition or static alias to its supported public export. Smelt verifies both against the same static identity, including supported literal lazy-export tables; missing, conflicting or unsupported dynamic owners are configuration errors. A verified owner prevents duplicate export advice for that symbol only. Importer context separates same-root and other-root production consumers. Ownership never relaxes layers, package-public contracts or cycle checks; without declarations existing thresholds behave as before.

## Bad

```python
# app/browser/__init__.py is empty
# Three outside modules each use:
from app.browser.base import BrowserEvents
```

## Good

```python
# After reviewing ownership and initialization behavior:
# app/browser/__init__.py
from .base import BrowserEvents
__all__ = ['BrowserEvents']
# callers
from app.browser import BrowserEvents
```

## How to fix

Review whether the name belongs in the package API or whether callers should move. The finding lists importers and other public export paths. A cycle witness means adding the facade dependency closes a runtime import path; no-cycle-found means only that no return path was found in the analyzed explicit module graph, not that initialization is safe. Dynamic imports, implicit package initialization and import order are not proven. No exports, imports or policy are rewritten automatically.

## Config

- `structure.contracts`
- `structure.canonical_exports`

Explain it in the terminal with `smelt explain SMT109`.
