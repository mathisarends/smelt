# SMT341 mixed-str-enum-values

A StrEnum mixes auto() members with explicit string values.

- **Category:** structure
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** hint

## Why

A StrEnum should declare its values in one canonical form: either every member uses auto(), which derives the lowercased member name, or every member spells its string explicitly. Mixing both hides which values are wire contracts and which are derived, and makes readers check each line. This opt-in review reports classes in production code that inherit directly from enum.StrEnum (imported as StrEnum, an alias or enum.StrEnum) and declare at least one auto() member and at least one string literal member. Member aliases, private names and other assignments are ignored. Tests are not checked.

## Bad

```python
class SignalingMessageType(StrEnum):
    DESCRIPTION = auto()
    CANDIDATE = "candidate"
    READY = auto()
```

## Good

```python
class SignalingMessageType(StrEnum):
    DESCRIPTION = auto()
    CANDIDATE = auto()
    READY = auto()
```

## How to fix

When every explicit string equals the lowercased member name, replace those strings with auto(). Otherwise the explicit values are deliberate, so spell every auto() member as its lowercased name instead. The finding names the suggested style. No automatic rewrite is performed. Enable rules: {mixed-str-enum-values: hint}, or select SMT341. Package overrides and reasoned inline suppressions are supported.
