# SMT318 redundant-str-enum-value

Review .value on a known StrEnum member for direct use of the member.

- **Category:** structure
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** hint

## Why

StrEnum members are already strings, so extracting .value often adds noise and loses the enum type unnecessarily. This opt-in hint recognizes direct Class.MEMBER.value reads on analyzed, top-level classes inheriting directly from enum.StrEnum, including import aliases, relative imports and analyzed re-exports. Simple string, auto() and member-alias declarations are supported. Ordinary Enum, str/Enum mixins, unknown or shadowed bindings, custom enum construction/value access, instance variables and dynamic lookups are excluded. Shadowing anywhere in a module conservatively limits recognition there.

## Bad

```python
from enum import StrEnum

class MouseEventKind(StrEnum):
    WHEEL = "mouseWheel"

dispatch_mouse_event(type=MouseEventKind.WHEEL.value)
```

## Good

```python
from enum import StrEnum

class MouseEventKind(StrEnum):
    WHEEL = "mouseWheel"

dispatch_mouse_event(type=MouseEventKind.WHEEL)
```

## How to fix

Prefer the member directly when the consumer accepts string subclasses. Review boundary behavior first: exact str checks, identity, repr and serialization contracts can distinguish the member from its raw value. Keep .value or an explicit str(member) conversion where a plain string is intentional, and suppress the hint with a reason. No automatic rewrite is performed; analyzed code is never executed.
