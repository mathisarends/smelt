# SMT308 import-style

An import does not follow the package's declared relative/absolute style.

- **Category:** structure
- **Activation:** policy — A package contract declares an imports style.
- **Severity when active:** error

## Why

A predictable import style makes ownership easier to read. With relative style and max_relative_level: 1, local imports use one dot; parent and cross-root imports stay absolute. Deeper relative imports can be explicitly allowed. The closest package contract supplies the style. No style is enforced without an explicit contract, and this rule never changes bindings.

## Bad

```python
# app/storage/service.py, relative style with maximum 1
from app.storage.models import Record
from ..domain import Entity
```

## Good

```python
# app/storage/service.py
from .models import Record
from app.domain import Entity
```

## How to fix

Use a relative import within the configured dot limit, otherwise use an absolute import. Preserve aliases and update references if converting an import statement changes its binding. There is no automatic rewrite.

## Config

- `structure.contracts`
- `architecture.imports.type_checking`

Explain it in the terminal with `smelt explain SMT308`.
