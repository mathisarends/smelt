# SMT426 test-deadline

A known test wait has no local deadline, or the scheduler clock is replaced.

- **Category:** tests
- **Activation:** policy — tests.review_test_deadlines is enabled.
- **Severity when active:** warning

## Why

A wedged subprocess or known Event.wait can hang a suite. This opt-in review aid checks subprocess.run/call/check_call/check_output and typed Popen wait/communicate calls for their own timeout, and awaited asyncio Event.wait calls for enclosing wait_for or timeout contexts. Configured qualified timeout helpers can supply guards. Unknown/transitive waits, external test-runner deadlines and general task flow are outside scope. Replacing the time method on a known running asyncio loop is reported separately because deadlines on that same clock can stop too. Controlled domain clocks, positive sleeps and sleep(0) yields are not prohibited.

## Bad

```python
def test_import():
    subprocess.run([sys.executable, '-c', 'import app'], check=True)
```

## Good

```python
def test_import():
    result = subprocess.run([sys.executable, '-c', 'import app'], capture_output=True, timeout=10)
    assert result.returncode == 0, result.stderr
```

## How to fix

Use a timeout at the blocking process boundary or around a known async wait. When replacing the scheduler clock, retain an independent real-time guard such as a parent-process timeout. Preserve bounded polling at real external boundaries.

## Config

- `tests.review_test_deadlines`
- `tests.timeout_helpers`
- `tests.quality_exclude`

Explain it in the terminal with `smelt explain SMT426`.
