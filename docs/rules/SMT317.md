# SMT317 prefer-private-module-function

An internal static helper can be reviewed for extraction to a private module function.

- **Category:** structure
- **Activation:** policy — A package contract sets static_methods to module-functions.
- **Severity when active:** hint

## Why

A helper that needs neither instance nor class state is often easier to find and reuse as a private module function. This package convention reviews direct sync/async methods carrying only the recognized builtin staticmethod decorator, including import aliases. Known or unresolved external same-named attribute access preserves static APIs. Classes with inheritance, subclasses or decorators, additional method decorators, special methods, __class__/super references and detected class-namespace dependencies are excluded. This is a placement preference, not proof of equivalent runtime behavior; external/dynamic consumers and definition-time dependencies still need review.

## Bad

```python
class Browser:
    @staticmethod
    def _normalize(value):
        return value.strip()
    def send(self, value):
        return self._normalize(value)
```

## Good

```python
def _normalize(value):
    return value.strip()

class Browser:
    def send(self, value):
        return _normalize(value)
```

## How to fix

Move the helper to module scope with a leading underscore, remove @staticmethod, and update class/instance-qualified calls and callback references. Preserve annotations, defaults, evaluation order and dependencies; choose a distinct name if the module already binds it. Keep deliberate static APIs with a closest allow override or reasoned suppression. No automatic extraction is performed.
