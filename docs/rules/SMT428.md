# SMT428 async-mock-without-await-check

A known async mock is checked for calls without corresponding await evidence.

- **Category:** tests
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** warning

## Why

Calling an async mock can leave its coroutine unexecuted while call assertions still pass. This opt-in review checks direct known AsyncMock callables and explicitly async methods of known Mock/AsyncMock class specs, including aliases and consistent direct fixture returns. It accepts await assertions/history checks on the same mock and explicit negative call checks. Simple single-assignment locals can carry history values into assertions. Unknown specs, inherited or dynamically replaced methods, nested helpers and general data flow are not inferred. An AsyncMock object's arbitrary children are not assumed async. Deliberate creation/scheduling tests can assert_not_awaited or use a reasoned exception. This is evidence about an individual test, not proof that the suite misses a regression.

## Bad

```python
def test_connect():
    connect = AsyncMock()
    run_handler(connect)
    connect.assert_called_once_with('account')
```

## Good

```python
def test_connect():
    connect = AsyncMock()
    run_handler(connect)
    connect.assert_awaited_once_with('account')
```

## How to fix

When execution matters, check await arguments/counts or assert_awaited_once_with on this async mock. Preserve intentional scheduling tests with an explicit expectation; keep synchronous interactions unchanged.
