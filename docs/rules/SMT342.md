# SMT342 str-enum-explicit-values

A StrEnum derives a value with auto().

- **Category:** structure
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** hint

## Why

This opt-in style rule makes explicit strings the project convention for StrEnum values: every value is visible where it is declared and renaming a member cannot silently change a serialized value. A class is reported when a member uses auto(). Do not enable it together with SMT341 str-enum-auto-values, which states the opposite convention. It considers production classes inheriting directly from enum.StrEnum (imported as StrEnum, an alias or enum.StrEnum). Member aliases, private names and tests are ignored.

## Bad

```python
class SignalingMessageType(StrEnum):
    DESCRIPTION = auto()
    READY = auto()
```

## Good

```python
class SignalingMessageType(StrEnum):
    DESCRIPTION = "description"
    READY = "ready"
```

## How to fix

Spell each reported auto() member as its lowercased name, the value auto() produces for a StrEnum. No automatic rewrite is performed. Enable rules: {str-enum-explicit-values: hint}, or select SMT342. Package overrides and reasoned inline suppressions are supported.

## Config

- `rules`

Explain it in the terminal with `smelt explain SMT342`.
