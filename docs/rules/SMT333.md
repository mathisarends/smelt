# SMT333 prefer-callable-instance

Review __call__ and an operation-based class name for a single public method.

- **Category:** structure
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** hint

## Why

A class with one public instance method can express its operation through __call__ and a class name describing that operation. This opt-in design review reports one candidate per plain class with exactly one directly declared public method. Private helpers and __init__ do not count as public operations. An existing __call__ is already a callable API and is never reported. Constructor and operation signatures are reported separately, including positional-only, keyword-only and variadic arguments: construction configures the object, while __call__ must retain the method's call-time arguments and async behavior. Classes with bases, metaclass keywords, class or method decorators, additional special methods, class-level data or conditional definitions are excluded. This keeps inherited APIs, descriptors, dataclasses and explicit protocols outside this bounded syntax review. Test files are excluded. A single method does not prove a design defect: published named APIs and stateful lifecycles can justify keeping the class as it is. Dynamic monkey-patching and external API consumers are not resolved.

## Bad

```python
class ReportService:
    def __init__(self, storage):
        self._storage = storage

    def generate(self, report_id, *, refresh=False):
        return self._storage.load(report_id, refresh=refresh)
```

## Good

```python
class GenerateReport:
    def __init__(self, storage):
        self._storage = storage

    def __call__(self, report_id, *, refresh=False):
        return self._storage.load(report_id, refresh=refresh)
```

## How to fix

Consider renaming the sole public method to __call__ and naming the class after its operation (for example, ReportService.generate becomes GenerateReport.__call__). Preserve the constructor signature, call-time parameters, defaults, return annotations and async behavior; do not move constructor dependencies into __call__. Review callers, dependency injection registrations and public compatibility before changing either name. No names, arguments or callers are rewritten automatically. Enable rules: {prefer-callable-instance: hint}, globally or in a package contract, or --select SMT333. Keep an intentional named API with a package rules override set to off or a reasoned SMT333 suppression.
