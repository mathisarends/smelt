# SMT322 deep-object-navigation

Review a method call reached through multiple instance attributes.

- **Category:** structure
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** hint

## Why

An instance method that reaches through several stored collaborators depends on their internal arrangement. This opt-in Law of Demeter review reports calls with at least two consecutive attribute accesses from the instance receiver before the first method call, such as self.browser.input.motor(). One finding covers a whole receiver call chain. Direct collaborator calls, pure data reads and fluent chains starting from a direct collaborator are excluded. Module objects stored from unshadowed imports or declared as ModuleType, explicit SimpleNamespace trees, and typed dataclass/Pydantic record paths ending in known containers or values are namespaces rather than collaborator graphs. Known pathlib parent paths and subprocess pipes also retain their standard APIs. Namespace evidence comes from annotations, direct constructor assignments and property return annotations; analyzed imports and re-exports are followed without executing code. Every intermediate object must be a known namespace or value: a record containing a service does not exempt navigation into that service. Names such as api, client, get or append alone exempt nothing. Unknown SDK types and dynamic property/data flow remain review limitations. Decorated and implicit class/static methods, nested helper bodies, comprehensions, receiver rebinding and navigation through parameters, aliases or subscripts are outside the review. This is a bounded review, not proof of a design defect.

## Bad

```python
class Controller:
    def aim(self, width, height):
        return self.browser.input.motor().aim(width, height)
```

## Good

```python
class Controller:
    def __init__(self, motor):
        self.motor = motor

    def aim(self, width, height):
        return self.motor.aim(width, height)
```

## How to fix

Review whether the caller should receive the needed collaborator directly or ask its direct collaborator to perform the operation. A local variable alone does not reduce structural coupling. Preserve factory/property evaluation and object lifetimes; repeated lookups need not return the same object. Keep intentional API navigation with a package rules override set to off or a reasoned SMT322 suppression. No automatic rewrite is performed. Enable with rules: {deep-object-navigation: hint}, globally or in a package contract, or --select SMT322.
