# SMT424 missing-test-assertion

A collected test has no recognized explicit outcome assertion.

- **Category:** tests
- **Default severity:** warning

## Why

A test that merely calls production code can pass when its result is wrong. This opt-in syntactic check accepts assert (except literal assert True), pytest.raises/warns/deprecated_call, unittest.TestCase assertion calls and configured qualified assertion helpers. Nested functions and fixture bodies do not supply evidence to their caller. It neither proves assertions execute nor judges their strength. Smoke tests and interaction-only boundary tests can be intentional exceptions.

## Bad

```python
def test_deactivate():
    deactivate_user(1)
```

## Good

```python
def test_deactivate():
    user = deactivate_user(1)
    assert user.status == 'inactive'
```

## How to fix

Assert a concrete result or observable state, check the expected exception/warning, or configure a known assertion helper. Use a reasoned exception for deliberate smoke/interaction tests. Do not add a meaningless assertion to silence the finding.

## Config

- `tests.require_assertions`
- `tests.assertion_helpers`
- `tests.quality_exclude`

Explain it in the terminal with `smelt explain SMT424`.
