# SMT345 excess-positional-parameters

A function accepts more positional parameters than its package allows.

- **Category:** structure
- **Activation:** policy — A package contract sets max_positional_parameters, including zero.
- **Severity when active:** warning

## Why

Call sites such as connect(user, run, tab, True) do not say which value is which, and swapping two arguments of the same type still type-checks. A package contract sets max_positional_parameters; parameters after that limit must be keyword-only so every call names them. self and cls are not counted, nor are *args and **kwargs. Dunder methods, @overload and @override definitions are exempt because their signatures are dictated elsewhere, and tests are not checked. Positional-only parameters count like any other positional parameter.

## Bad

```python
def connect(user_id: UUID, run_id: UUID, tab_id: UUID) -> None:
    ...
```

## Good

```python
def connect(user_id: UUID, *, run_id: UUID, tab_id: UUID) -> None:
    ...
```

## How to fix

Insert * after the last allowed positional parameter, then pass the remaining arguments by keyword at every call site. Callbacks whose positional signature is fixed by a framework keep it with a reasoned suppression. No automatic rewrite is performed. Enable it with a package contract, e.g. structure.contracts.<name>: {match: app, max_positional_parameters: 2}.

## Config

- `structure.contracts`

Explain it in the terminal with `smelt explain SMT345`.
