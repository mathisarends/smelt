# SMT422 string-patch-target

A recognized patch call or decorator uses a literal string target.

- **Category:** tests
- **Activation:** policy — tests.forbid_string_patch_targets is enabled.
- **Severity when active:** error

## Why

String patch targets encode import paths that refactoring tools may not update. This opt-in convention checks unittest.mock and standard pytest-mock patch, patch.dict and patch.multiple literal targets. It does not claim that patch.object removes implementation coupling; variables and dynamically computed targets are outside this syntax check.

## Bad

```python
from unittest.mock import patch
@patch("app.service.Repository")
def test_run(repository): ...
```

## Good

```python
def test_run():
    repository = InMemoryRepository()
    run(repository)
    assert repository.saved == [42]
```

## How to fix

Prefer an injected collaborator/fake. For deliberate boundary patching, use object-based patching where appropriate and patch the name looked up by the caller. No automatic rewrite is performed.

## Config

- `tests.forbid_string_patch_targets`
- `tests.quality_exclude`

Explain it in the terminal with `smelt explain SMT422`.
