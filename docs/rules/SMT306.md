# SMT306 incomplete-coverage

Strict coverage found source outside the architecture policy or an exclusion without a reason.

- **Category:** structure
- **Activation:** policy — project.coverage is strict, including --strict-coverage; the guard cannot be disabled in strict mode.
- **Severity when active:** error

## Why

A passing architecture check is only useful when production code cannot silently escape its package selection or classification. Strict coverage inventories source roots and Python workspace members independently of project.root_packages. Pure package facades do not need their own layer.

## Bad

```yaml
# smelt.yaml
project:
  root_packages: [backend]
  coverage: strict
# A new workspace library exists but is not selected or classified.
```

## Good

```yaml
# smelt.yaml
project:
  root_packages: [backend, client]
  source_roots: [backend/src, libs/client/src]
  coverage: strict
architecture:
  modules: {client: infrastructure}
```

## How to fix

Select missing production packages and assign their architecture role. Move unclassified implementation into an existing layer. Deliberately excluded code needs project.exclude entries with path and reason. Coverage gaps cannot be hidden by debt, inline ignores or a narrowed check.

## Config

- `project.coverage`
- `project.root_packages`
- `project.source_roots`
- `project.exclude`
- `architecture.modules`

Explain it in the terminal with `smelt explain SMT306`.
