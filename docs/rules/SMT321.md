# SMT321 implicit-optional-default

An optional parameter with a None default uses truthiness to choose a fallback.

- **Category:** structure
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** warning

## Why

For an explicitly optional parameter, None commonly means not supplied. Using parameter or fallback also replaces valid falsy values such as zero, empty strings, empty containers and objects with custom truthiness. This opt-in review recognizes two-operand or expressions whose first operand is a directly named, unrebound parameter with a literal None default and a syntactic optional annotation (including quoted unions and typing Optional/Union/Annotated). It skips nested scopes, boolean tests, and parameters rebound anywhere in their function. Intentional falsy defaults remain valid; suppress or disable the review there. This is bounded syntax analysis, not type or control-flow inference.

## Bad

```python
def create(options: Options | None = None):
    self.options = options or Options()
```

## Good

```python
def create(options: Options | None = None):
    self.options = options if options is not None else Options()
```

## How to fix

Review whether only None should select the fallback. If so, use parameter if parameter is not None else fallback. smelt check --select SMT321 --fix --unsafe-fixes applies this behavior-changing rewrite only to visible findings. Plain --fix leaves it unchanged. The rewrite preserves fallback laziness and source outside each expression; inline comments or explicit line continuations within an expression require manual editing. Intentional truthiness fallback should remain unchanged.
