# SMT337 deprecated-async-contextmanager-return

An @asynccontextmanager function annotates its return as AsyncIterator[T].

- **Category:** structure
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** warning

## Why

The contextlib.asynccontextmanager decorator remains supported. Typeshed deprecates its AsyncIterator overload because the decorator consumes an async generator, including its athrow/aclose methods. Use AsyncGenerator[T, None] to express that contract explicitly; the second argument also works on Python 3.12. This opt-in check provides the same guidance without requiring a type checker. It recognizes async functions and methods with direct AsyncIterator[T] annotations from collections.abc or typing, including quoted annotations, module/import aliases and guarded module-level imports such as TYPE_CHECKING. It conservatively skips names rebound anywhere in the file, wildcard imports, local imports, re-exports, user-defined types, type aliases and wrapped annotations. Ordinary async iterators and functions already annotated as AsyncGenerator remain valid. See https://github.com/python/typeshed/blob/main/stdlib/contextlib.pyi for the deprecated overload.

## Bad

```python
from collections.abc import AsyncIterator
from contextlib import asynccontextmanager

@asynccontextmanager
async def exclusive() -> AsyncIterator[None]:
    yield
```

## Good

```python
from collections.abc import AsyncGenerator
from contextlib import asynccontextmanager

@asynccontextmanager
async def exclusive() -> AsyncGenerator[None, None]:
    yield
```

## How to fix

Replace AsyncIterator[T] with AsyncGenerator[T, None] and import AsyncGenerator from collections.abc. Preserve the yielded type and the decorator, and remove the AsyncIterator import only if unused elsewhere. No automatic rewrite is performed. Enable rules: {deprecated-async-contextmanager-return: warning}, or select SMT337. Package overrides and reasoned inline suppressions are supported.
