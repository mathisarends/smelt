# SMT348 missing-interface-docstring

An abstract or Protocol method has a placeholder body and no docstring.

- **Category:** structure
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** hint

## Why

A port or interface method has no implementation to read, so its docstring is the only place that states the contract: what the method guarantees, what it requires and what it leaves untouched. A bare ... body leaves implementers and callers to guess, and one undocumented member next to documented siblings usually means the contract was forgotten, not that it is obvious. This opt-in review reports @abstractmethod methods (including abstract properties) and methods of typing.Protocol classes whose body is only ..., pass or raise NotImplementedError and which have no docstring. Methods with a default implementation, @overload/@override signatures, property setters/deleters, dunder methods other than __call__ and tests are not reported. Ordinary Protocol attributes have no body and are out of scope.

## Bad

```python
class BrowserAgentProfile(ABC):
    @property
    @abstractmethod
    def initial_tab_id(self) -> UUID: ...

    @abstractmethod
    async def revoke(self) -> None: ...
```

## Good

```python
class BrowserAgentProfile(ABC):
    @property
    @abstractmethod
    def initial_tab_id(self) -> UUID:
        """The tab retained when the profile grant was acquired."""

    @abstractmethod
    async def revoke(self) -> None:
        """Fence native access and settle all resource leases."""
```

## How to fix

Replace the placeholder body with a docstring that states the method's contract; a docstring alone is a valid body, so drop the ... (Ruff PIE790 reports a placeholder left after a docstring). No automatic rewrite is performed. Enable rules: {missing-interface-docstring: hint}, or select SMT348. Package overrides and reasoned inline suppressions are supported.
