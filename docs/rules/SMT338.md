# SMT338 duplicate-literal-type

Review repeated multi-value Literal types for a shared type alias.

- **Category:** structure
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** hint

## Why

Repeated Literal value sets can drift when a contract changes. This opt-in review groups identical raw value sets within each analyzed root package, including repetitions across modules. It reports one finding per participating file and value set, with related source locations. Direct typing/typing_extensions imports, import aliases, quoted annotations, nested explicit Literals, type aliases and Annotated's first argument are supported. Annotated metadata is never compared or treated as a type. Order and repeated members do not matter; values retain their Python types. Singleton Literals, enum members, named-alias expansion, uncertain imports, test files and separate root packages are excluded. Same-valued types can represent unrelated concepts, so this is a review hint rather than proof that they should share a name. Package rule overrides and suppressions govern findings at each participating file; other analyzed source files still contribute evidence.

## Bad

```python
from typing import Annotated, Literal
from pydantic import Field

type ClickButton = Annotated[Literal["left", "right"], Field(description="Mouse button")]

def click_message(button: Literal["left", "right"]) -> str:
    return button
```

## Good

```python
from typing import Annotated, Literal
from pydantic import Field

type MouseButton = Literal["left", "right"]
type ClickButton = Annotated[MouseButton, Field(description="Mouse button")]

def click_message(button: MouseButton) -> str:
    return button
```

## How to fix

Define or reuse a shared plain type alias when the occurrences describe the same concept. Keep Field descriptions and constraints on the Annotated wrappers that need them. Choose an owning module that respects architecture boundaries and avoids import cycles. Review Python-version, runtime annotation and schema behavior before changing aliases; use TypeAlias syntax where the supported Python version requires it. Suppress intentional independent contracts with a reason. No automatic rewrite is performed; analyzed code is never executed.
