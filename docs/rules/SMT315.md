# SMT315 prefer-match-type-dispatch

Review a same-subject isinstance/elif chain for match/case under an explicit package policy.

- **Category:** structure
- **Default severity:** hint

## Why

Long type-dispatch chains can be clearer as class patterns and guards. This opt-in hint recognizes positive builtin isinstance tests over the same simple name, optionally followed by and guards. It preserves independent adjacent if statements and reports one candidate per whole supported chain. It is a readability suggestion, not proof of equivalent class-pattern behavior.

## Bad

```python
if isinstance(event, Started):
    start(event)
elif isinstance(event, Delta | Progress):
    update(event)
elif isinstance(event, Finished) and event.ok:
    finish(event)
```

## Good

```python
match event:
    case Started():
        start(event)
    case Delta() | Progress():
        update(event)
    case Finished() if event.ok:
        finish(event)
```

## How to fix

Review class patterns, guards and subclass ordering. Preserve independent if statements, and keep nested body conditions inside their case: moving them into a case guard can introduce fallthrough. Match evaluates its subject once; custom instance checks, dynamic type expressions and side effects may differ. No automatic rewrite is performed. Declared Python minima before 3.10 are excluded; unknown minima require version review.
