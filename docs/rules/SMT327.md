# SMT327 secret-settings-field

A secret-named settings field accepts an unwrapped str or bytes value.

- **Category:** structure
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** warning

## Why

Pydantic SecretStr and SecretBytes mask ordinary string/repr/JSON representations. This opt-in review recognizes top-level, undecorated BaseSettings classes and same-file subclasses through stable direct import aliases. Secret names are password, passwd, secret, api_key, private_key, access_token, refresh_token and token, including underscore-delimited suffixes. It reviews str/bytes inside quoted annotations, unions, Optional and Annotated. Correct Secret types, unknown/custom types, cross-file inheritance, dynamic aliases and shadowed bindings are outside this check. Public keys, token counts and nonsecret settings remain valid. Field names are review evidence, not proof of sensitivity or absence of leaks. Defaults and secret values are never included in diagnostics.

## Bad

```python
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    api_key: str
    database_password: str | None = None
```

## Good

```python
from pydantic import SecretStr
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    api_key: SecretStr
    database_password: SecretStr | None = None
```

## How to fix

Use SecretStr for textual credentials or SecretBytes for binary credentials. Update deliberate plaintext consumers to unwrap explicitly and verify serialization. Keep nonsecret fields unchanged or suppress a misleading field name with a reason. No type annotations or consumers are rewritten automatically. Enable rules: {secret-settings-field: warning}; package overrides can restrict adoption.
