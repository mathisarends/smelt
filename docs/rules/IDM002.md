# IDM002 idioms/prefer-match-type-dispatch

Review a same-subject isinstance/elif chain or run of exiting isinstance guards for match/case under an explicit package policy.

- **Category:** idioms
- **Activation:** explicit — Enable by rule setting or --select; requires that style or a package override sets type_dispatch.style to match.
- **Severity when active:** hint
- **Automatic fix:** none; repair by hand
- **Guide:** Dispatch on the type of one subject with match/case instead of an isinstance chain

## Why

Long type-dispatch chains can be clearer as class patterns and guards. This opt-in hint recognizes positive builtin isinstance tests over the same simple name, optionally followed by and guards. It also treats a maximal run of adjacent guards on the same subject as one chain when every guard has no elif or else and its body ends in an unconditional return or raise: each later guard then only runs after the earlier tests failed. A guard that can fall through, an exit only in a nested branch, a statement between guards, another subject, a negative test or continue/break exits end the run. Other independent adjacent if statements are preserved, and each whole supported chain is reported once. It is a readability suggestion, not proof of equivalent class-pattern behavior.

## Bad

```python
if isinstance(event, Started):
    start(event)
elif isinstance(event, Delta | Progress):
    update(event)
elif isinstance(event, Finished) and event.ok:
    finish(event)
```

## Good

```python
match event:
    case Started():
        start(event)
    case Delta() | Progress():
        update(event)
    case Finished() if event.ok:
        finish(event)
```

## How to fix

Review class patterns, guards and subclass ordering. For a guard chain, move each guard body with its return or raise into its case and turn a return or raise right after the guards into case _:. Preserve independent if statements, and keep nested body conditions inside their case: moving them into a case guard can introduce fallthrough. Match evaluates its subject once; custom instance checks, dynamic type expressions and side effects may differ. No automatic rewrite is performed. Declared Python minima before 3.10 are excluded; unknown minima require version review.
