# SMT202 concrete-dependency

A parameter is annotated with a concrete adapter instead of its port.

- **Category:** code
- **Default severity:** warning

## Why

An annotation couples the signature to one implementation even when the import hides behind TYPE_CHECKING or a shared re-export, so SMT101 never sees it.

## Bad

```python
class StartSession:
    def __init__(self, sessions: SqlVoiceSessionRepository) -> None: ...
```

## Good

```python
class StartSession:
    def __init__(self, sessions: VoiceSessionRepository) -> None: ...
```

## How to fix

Annotate the parameter with the port the adapter implements.

## Config

- `roles.<role>.detect.implements`
- `roles.<role>.layers`

Explain it in the terminal with `smelt explain SMT202`.
