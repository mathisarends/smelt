# Documentation

Start with the [project overview and quick start](../README.md), then follow the
guide for the decision or task at hand:

| If you want to... | Read |
| --- | --- |
| Describe boundaries, features, layers or strict policy coverage | [Architecture as code](architecture.md) |
| Define package interfaces and source conventions | [Package contracts and source conventions](structure.md) |
| Configure test layout and quality checks | [Test policies](testing.md) |
| Understand configuration, overrides and editor support | [Configuration](configuration.md) |
| Choose checks and understand what enables them | [Rule activation](rule-selection.md) and the [rule catalog](rules/README.md) |
| Interpret commands, changed checks and machine-readable reports | [CLI and reports](cli.md) |
| Introduce Smelt to an existing codebase | [Adoption and debt](adoption.md) |
| Set up an agent loop, prek, pre-commit or CI | [Agents, hooks and CI](integrations.md) |
| Extend Smelt, run its checks or publish a release | [Contributing](../CONTRIBUTING.md) |
| Review staged agent changes, caching and performance | [Agent workflow](agent-workflow.md) |
| Understand project direction and known gaps | [Vision](vision.md) and [review backlog](review.md) |

The rule catalog and individual rule pages in `rules/` are generated from the
rule metadata. See [Contributing](../CONTRIBUTING.md) for how to update them.
