# SMT332 compose-file-name

A Compose filename uses a different basename from the project's canonical spelling.

- **Category:** structure
- **Activation:** policy — structure.file_naming.compose_basename selects a canonical Compose basename.
- **Severity when active:** error

## Why

Choose compose or docker-compose once in structure.file_naming.compose_basename. The policy recognizes compose.yaml, docker-compose.yml and dotted variants such as docker-compose.override.yaml or compose.prod.yml anywhere below the project root. Variant suffixes are preserved. Custom filenames such as stack.yaml and docker-compose-backup.yml are not classified by content. Extension consistency belongs solely to SMT331; either extension is valid when yaml_extension is omitted. No policy means no finding, including with --select ALL.

## Bad

```yaml
# With compose_basename: compose
# docker-compose.override.yaml
```

## Good

```yaml
# With compose_basename: compose
# compose.override.yaml
```

## How to fix

Rename to the expected path and update references such as docker compose -f arguments, scripts and CI. Check for existing destination files before renaming. Files and references are never changed automatically. Use a reasoned ignore.paths entry for an intentional exception.

## Config

- `structure.file_naming.compose_basename`
- `project.exclude`
- `ignore`

Explain it in the terminal with `smelt explain SMT332`.
