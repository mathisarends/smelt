# SMT346 prefer-deferred-annotations

An annotation is quoted where deferred evaluation makes quotes unnecessary.

- **Category:** structure
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** hint

## Why

Quoted annotations such as list["BrowserWorkspaceTab"] are invisible to rename refactorings, read differently from their neighbors and need a decision at every forward reference. One module-level from __future__ import annotations, or a declared Python 3.14+ minimum, defers every annotation instead. This opt-in style review reports one finding per module that quotes annotations of parameters, returns or annotated assignments: on 3.14+ targets or with the future import, the quotes are redundant; otherwise the module should add the future import. Strings inside Literal and Annotated metadata are values, not annotations, and are ignored, as are quoted names in runtime expressions such as cast() or TypeVar(bound=...). A package contract with future_annotations: forbid keeps quotes on targets before 3.14. Tests are not checked.

## Bad

```python
class BrowserHandoff(ABC):
    @abstractmethod
    async def tabs(self) -> list["BrowserWorkspaceTab"]: ...
```

## Good

```python
from __future__ import annotations

class BrowserHandoff(ABC):
    @abstractmethod
    async def tabs(self) -> list[BrowserWorkspaceTab]: ...
```

## How to fix

Remove the quotes; on targets before Python 3.14 add from __future__ import annotations first. The future import makes every annotation in the module a string at runtime, so verify runtime annotation consumers (dataclasses, Pydantic, FastAPI, dependency injection) and names imported only under TYPE_CHECKING. No automatic rewrite is performed. Enable rules: {prefer-deferred-annotations: hint}, or select SMT346.
