# SMT336 redundant-module-name

A module filename repeats context already supplied by an ancestor package.

- **Category:** structure
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** hint

## Why

cars.application.car_exporter repeats the cars context; cars.application.exporter keeps the responsibility visible without restating the path. This opt-in review checks a whole ancestor package name at either underscore-delimited end of a module name, including across intervening layer packages. It also recognizes a single regular trailing s (cars/car, purchase_orders/purchase_order). It does not infer irregular plurals or strip ss, us, is, ies, ses, xes, zes, ches or shes endings. Leading underscores are preserved. Substrings, names with no remaining responsibility, package names, dunder modules and separately discovered tests are outside scope. Source-root directory names are not package context. Findings are advisory because repetition may serve a published API or domain meaning.

## Bad

```text
backend/features/cars/application/car_exporter.py
```

## Good

```text
backend/features/cars/application/exporter.py
```

## How to fix

Review the shorter filename and update imports and facade exports when renaming. An occupied module/package name is not suggested. No files are renamed automatically. Enable with rules: {redundant-module-name: hint}, globally or in a package contract, or --select SMT336. Use a package off override or a reasoned file suppression for intentional public names.

## Config

- `rules`
- `structure.contracts`

Explain it in the terminal with `smelt explain SMT336`.
