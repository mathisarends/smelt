# SMT102 cross-feature-import

A feature imports another feature outside the allowed layer pairs.

- **Category:** dependencies
- **Activation:** policy — architecture.features defines feature boundaries.
- **Severity when active:** error

## Why

Features are independent slices. Direct imports between them couple release cycles and make it impossible to reason about one feature in isolation. With architecture.imports.transitive, allowed pairs also apply to all reachable feature modules, with a shortest import chain as evidence.

## Bad

```python
# billing/infra/charges.py
from gateway.features.voice.infra.sql import CallLog
```

## Good

```python
# billing/application/charges.py
from gateway.features.voice.application.api import CallSummaryQuery
```

## How to fix

Go through an allowed relationship, declare an intended one explicitly (`allow: [{from: orders.application, to: billing.application}]`), move the shared concept into a `shared` package, or merge the features.

## Config

- `architecture.cross_feature.default`
- `architecture.cross_feature.allow`
- `architecture.imports.transitive`
- `architecture.imports.type_checking`

Explain it in the terminal with `smelt explain SMT102`.
