# SMT329 caller-before-callee

A direct caller appears after same-visibility helpers it calls.

- **Category:** structure
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** hint

## Why

A step-down reading order introduces a higher-level operation before its lower-level helpers. This opt-in review covers stable undecorated top-level sync/async functions and direct methods on undecorated classes without bases. It resolves direct same-module names and receiver.method calls, excludes shadowed bindings, nested scopes, comprehensions, dunder methods and recursive call components, and respects definition-time parameter/return dependencies. Only same-visibility pairs are reviewed so SMT313's public-first categories retain precedence. Dynamic lookup, inherited APIs and general call graphs are not inferred. This is a reading convention, not a correctness check.

## Bad

```python
def parse():
    return 1

def load():
    return parse()
```

## Good

```python
def load():
    return parse()

def parse():
    return 1
```

## How to fix

Review placing the caller before its helper within the same public/private group. Preserve defaults, decorators, annotations, rebinding and execution barriers. No definitions are reordered automatically; SMT313 independently handles public-first ordering and its bounded fixer. Enable rules: {caller-before-callee: hint} or select SMT329; package overrides and reasoned suppressions apply.
