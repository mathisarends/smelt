# SMT320 internal-public-module-symbol

A public module constant or type alias has no observed external use or public-signature evidence.

- **Category:** structure
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** warning

## Why

Public-looking module data can advertise implementation details. This opt-in review covers single, unconditional uppercase assignments and PEP 695 type aliases in implementation modules. Imports, analyzed re-exports, test accesses, escaped modules, static __all__ exports and public signatures preserve names. Alias dependencies in public annotations are followed, including quoted annotations. Package initializers, rebound or shadowed names, star imports, dynamic exports and detected namespace reflection are excluded. Ordinary assignment-style type aliases and class visibility are outside this check. Excluded files, unselected packages and external or arbitrary dynamic consumers remain unassessed; findings expose usage_scope and do not prove a rename is safe.

## Bad

```python
MIN_LENGTH = 8
type Payload = str | bytes

def _valid(value: Payload):
    return len(value) >= MIN_LENGTH
```

## Good

```python
_MIN_LENGTH = 8
type _Payload = str | bytes

def _valid(value: _Payload):
    return len(value) >= _MIN_LENGTH
```

## How to fix

Review the intended API and callers. Make genuine implementation details private, updating references and quoted annotations. Preserve supported public names with __all__ or a reasoned suppression. A type alias used in a public signature is API evidence, not a private-name candidate; this rule does not require exporting every annotation dependency. No automatic rename is performed.
