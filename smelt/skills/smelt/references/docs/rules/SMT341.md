# SMT341 str-enum-auto-values

A StrEnum spells a value that auto() derives.

- **Category:** structure
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** hint

## Why

This opt-in style rule makes auto() the project convention for StrEnum values: auto() derives the lowercased member name, so an explicit string repeating it is noise and hides which values are deliberate wire contracts. A class is reported when an explicit string equals the lowercased member name. A class with custom values such as 'mouseMoved' keeps explicit strings for every member; there, auto() members are reported instead. Do not enable it together with SMT342 str-enum-explicit-values, which states the opposite convention. It considers production classes inheriting directly from enum.StrEnum (imported as StrEnum, an alias or enum.StrEnum). Member aliases, private names and tests are ignored.

## Bad

```python
class ConnectionState(StrEnum):
    OPEN = "open"
    CLOSED = "closed"
```

## Good

```python
class ConnectionState(StrEnum):
    OPEN = auto()
    CLOSED = auto()
```

## How to fix

Replace each reported explicit string with auto(). In a class with custom values, spell the reported auto() members as their lowercased names instead. No automatic rewrite is performed. Enable rules: {str-enum-auto-values: hint}, or select SMT341. Package overrides and reasoned inline suppressions are supported.
