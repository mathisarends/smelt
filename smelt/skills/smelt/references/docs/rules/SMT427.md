# SMT427 independent-test-case-loop

A small literal loop repeats a candidate independent arrange/action/assert case.

- **Category:** tests
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** hint

## Why

A failure in the first independent case prevents later loop iterations from running and obscures case selection. This opt-in review aid considers top-level loops over 2-12 literal list/tuple cases with per-iteration construction/action and assertions. It excludes branches, context managers, control transfers, accumulated state, attribute writes and calls on pre-existing receivers. These exclusions preserve common replay, ownership-handoff and transaction/stream lifecycles. Independence cannot be proven syntactically; repeated calls alone and line counts are not smells.

## Bad

```python
def test_select():
    for path in ['app/a.py', 'app/b.py']:
        selected = select(path)
        assert selected == ['app']
```

## Good

```python
@pytest.mark.parametrize('path', ['app/a.py', 'app/b.py'], ids=['a', 'b'])
def test_select(path):
    assert select(path) == ['app']
```

## How to fix

Review whether cases are independent, then use pytest.mark.parametrize with meaningful IDs. Retain loops when later actions depend on earlier state.

- `rules`
- `tests.quality_exclude`
