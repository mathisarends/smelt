# SMT323 no-base-class-prefix

A class definition uses the Base prefix forbidden by the selected naming convention.

- **Category:** structure
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** error

## Why

BaseService names a position in an inheritance hierarchy rather than the abstraction's responsibility. A responsibility-based name such as Service keeps that implementation choice out of the name. The prefix does not itself create additional dependency coupling, and inheritance can be intentional, so this is an opt-in naming convention rather than a correctness check or an inheritance ban. It checks all class definitions in matching production modules, including private, nested and local classes, without inferring whether they have subclasses. After leading underscores, Base must be the whole name or be followed by an uppercase letter or underscore. Baseline, Baseball and Base64 remain valid. Imports, aliases, function names and test files are outside scope; inheriting from an imported BaseModel is allowed.

## Bad

```python
class BaseRepository:
    ...

class SqlRepository(BaseRepository):
    ...
```

## Good

```python
class Repository:
    ...

class SqlRepository(Repository):
    ...
```

## How to fix

Choose a name describing the class's responsibility or contract, then update references and deliberate exports. Preserve inheritance where it serves the design. A more specific package rule can disable the convention for compatibility. No symbols are renamed automatically. Enable with rules: {no-base-class-prefix: error}, globally or in a package contract, or --select SMT323.

## Config

- `rules`
- `structure.contracts`

Explain it in the terminal with `smelt explain SMT323`.
