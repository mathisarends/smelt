# CPX009 complexity/duplicate-parameter-group

A group of parameter names travels together through several functions.

- **Category:** complexity
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** hint
- **Automatic fix:** none; repair by hand
- **Guide:** Pass a group of values that travel together as one named value object
- **Smell:** The same five or more parameters are passed together through several unrelated functions.
- **No smell:** Parameters that only share their names and do not form one concept; keep them separate with a reasoned suppression.
- **Fix:** Name the concept as one value object, such as a frozen dataclass, and pass it instead, starting at the outermost caller.

## Why

When the same values are passed together through several functions, each caller repeats the whole list and adding a field means editing every signature. The values usually form a concept that wants a name. The opt-in hint compares the named parameters of production functions and methods, without self, cls, *args and **kwargs, and reports a group of at least 5 names shared by at least 3 functions once, at its first definition, with every location. The functions must belong to at least 2 override families. Methods with the same name form one family, which covers overrides, Protocol and ABC implementations and signatures that an outside base class dictates. A function that passes at least 5 of its parameters on to self.<method>, super().<method>, <ProjectClass>.<method>, a project function, a project class or cls() constructor joins that callee's family, so forwarding wrappers, factories and DI providers that mirror a constructor stay quiet. @overload stubs, tests and excluded files are ignored. Matching on names cannot prove that the values mean the same thing; the thresholds and the family requirement keep unrelated collisions rare. The diagnostic lists annotations that all locations share.

## Bad

```python
def listen(event_name, event_type, max_queue_size, overflow, timeout_seconds): ...
def listen_all(event_name, event_type, max_queue_size, overflow, timeout_seconds): ...
def subscribe(event_name, event_type, max_queue_size, overflow, timeout_seconds): ...
```

## Good

```python
@dataclass(frozen=True, slots=True)
class Subscription:
    event_name: str
    event_type: type[Event]
    max_queue_size: int
    overflow: Overflow
    timeout_seconds: float

def listen(subscription: Subscription): ...
def listen_all(subscription: Subscription): ...
def subscribe(subscription: Subscription): ...
```

## How to fix

Review the locations together. If the names describe one concept, introduce a value object such as a frozen dataclass and pass it instead of the separate parameters, starting at the outermost caller. Keep separate parameters when the values only share names. No automatic rewrite is performed.
