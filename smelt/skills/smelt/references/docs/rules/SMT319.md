# SMT319 prefer-package-import

Prefer an existing package re-export over an implementation import.

- **Category:** structure
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** hint

## Why

Importing supported names from a common package keeps callers independent of implementation paths and allows related imports to be combined. This opt-in hint requires every name in a from-import to have an unconditional, direct, same-named public re-export in an analyzed ancestor __init__.py. The nearest eligible package is suggested. Static __all__ is respected. Imports inside that package are excluded to avoid routing its own implementation through its initializer. Imports in package initializers also stay unchanged. Conditional, rebound, private, star and dynamic exports, re-export chains, module imports and unscanned third-party packages are outside this check.

## Bad

```python
# app/observation/__init__.py exports Observe and Snapshot
# app/client.py
from app.observation import Observe
from app.observation.models import Snapshot
```

## Good

```python
# app/client.py
from app.observation import Observe, Snapshot
```

## How to fix

Use the suggested package import and combine it with an existing import there when both are in the same scope and guard. Preserve aliases, comments and relative/absolute import policy. Review initializer side effects and dependency cycles. No exports are created and no automatic rewrite is performed; analyzed code is never executed.

- `rules`
- `architecture.imports.type_checking`
