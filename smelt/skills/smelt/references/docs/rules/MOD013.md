# MOD013 modeling/prefer-error-name

An exception class or module is named with Exception instead of Error.

- **Category:** modeling
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** error
- **Automatic fix:** none; repair by hand
- **Guide:** Name exception classes with an Error suffix and their module errors
- **Smell:** An exception class ends in Exception, or a module or package is named exception or exceptions.
- **No smell:** A published name that code outside the project imports or catches; keep it with a reasoned suppression.
- **Fix:** Rename to the suggested name and update imports, except clauses and exports; merge into an existing errors module.

## Why

PEP 8 names exceptions that signal errors with an Error suffix, as the builtins ValueError and OSError do. Mixing ParseException with ParseError, or exceptions.py with errors.py, leaves readers and agents guessing which spelling a project uses. This opt-in convention settles on Error. A class is reported when its name ends in Exception after a non-empty stem and a base names an exception: it ends in Error, Exception or Warning, is a builtin such as KeyboardInterrupt or ExceptionGroup, or is an exception class of the same module. Imported bases are judged by their names only, so a subclass of an imported Failure class is not recognised. Modules and packages named exception or exceptions are reported, with or without leading underscores. Names that merely mention exceptions, such as ExceptionHandler or exception_handlers.py, signals that are not errors, such as Cancelled, the builtin Exception itself and test files are outside scope.

## Bad

```python
# app/exceptions.py
class AppException(Exception):
    ...

class ParseException(AppException):
    ...
```

## Good

```python
# app/errors.py
class AppError(Exception):
    ...

class ParseError(AppError):
    ...
```

## How to fix

Rename the class to the suggested Error name and the module or package to errors, then update imports, except clauses and deliberate exports. When errors already exists, merge the two. A reasoned suppression can preserve a published name. No symbols or files are renamed automatically. Enable with rules: {modeling/prefer-error-name: error}, globally or in a style override, or --select MOD013.

## Config

- `rules`
- `style.overrides`

Explain it in the terminal with `smelt explain MOD013`.
