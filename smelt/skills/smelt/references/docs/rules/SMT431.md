# SMT431 nondeterministic-test-data

A test module calls a known random or time-derived data generator.

- **Category:** tests
- **Activation:** explicit — Enable by rule setting or --select.
- **Severity when active:** warning

## Why

Fixed IDs and values keep ordinary test setup reproducible and make failures easier to replay. This opt-in review recognizes direct uuid1/uuid4, os.urandom, secrets and common module-level random calls, including resolved import aliases and fixture/helper bodies in analyzed test modules. It groups calls on one source line. It does not infer whether randomness is the behavior under test. Seeded Random instances and unknown generators are outside scope; module-level random calls are reviewed even if a seed was set elsewhere. Production source and test-quality exclusions are not checked.

## Bad

```python
from uuid import uuid4

def test_create():
    lease = create(uuid4(), uuid4())
    assert lease.active
```

## Good

```python
from uuid import UUID

def test_create():
    lease = create(UUID(int=1), UUID(int=2))
    assert lease.active
```

## How to fix

Use fixed inputs such as UUID(int=1), or an explicitly seeded local random.Random(seed) when generated variation matters. Keep tests of randomness, entropy and unique-ID behavior with a reasoned suppression. Preserve falsy-ID regression scenarios; change only incidental random setup. No source is rewritten. Enable rules: {nondeterministic-test-data: warning} or select SMT431.

## Config

- `rules`
- `tests.quality_exclude`

Explain it in the terminal with `smelt explain SMT431`.
