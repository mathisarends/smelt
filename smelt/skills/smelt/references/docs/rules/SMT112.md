# SMT112 architecture/undeclared-member-dependency

A workspace member imports another member without declaring a direct project dependency.

- **Category:** architecture
- **Activation:** policy — project.workspace is uv; static member metadata declares dependencies.
- **Severity when active:** error

## Why

One shared import graph makes undeclared imports work locally, but the member may fail when installed independently. This rule compares direct production imports with project.dependencies, project.optional-dependencies and tool.uv.sources. Distribution names are normalized independently of Python package names. Markers and extras count without evaluating the analyzer's environment. uv sources alone do not declare dependencies. A member source overrides the root source, even when marked. Dependency groups and test imports are not assessed; projects with dynamic dependencies or without static metadata are skipped. architecture.imports.transitive does not require transitive declarations.

## Bad

```toml
[project]
name = "api"
dependencies = []
# api imports core.model
```

## Good

```toml
[project]
name = "api"
dependencies = ["core-lib"]
[tool.uv.sources]
core-lib = {workspace = true}
```

## How to fix

Declare the imported member's distribution in the importing member's project.dependencies and configure its uv workspace source; remove the import if the dependency is unintended.

## Config

- `project.workspace`
- `architecture.imports.type_checking`

Explain it in the terminal with `smelt explain SMT112`.
